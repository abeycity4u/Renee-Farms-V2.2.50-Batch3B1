## Source-level architecture inspection (One fix, fit it all)

- `lib/daily_feed_sync.php::sync_daily_feed_usage()` requires caller-owned PDO transaction, then locks and resolves the saved Daily Record through `daily_feed_sync_authoritative_cycle_guard()` / `stock_consumption_source_resolver_resolve()`, before accessing stock movements. It refuses forged cycle attribution and returns without writing on identical feed-item, quantity, cycle and date replay.
- A changed feed source first reverses the current active `USED` transaction through `stock_reverse_transaction()` with source type `daily_layer_record_reversal` and source ID the saved Daily Record, then creates the new `USED` through `stock_apply_movement()`. A correction to zero or feed removal reverses without replacement. `delete_daily_feed_usage()` uses the identical source→stock lock/ownership contract and becomes a no-op once no active USED exists.
- `lib/stock_service.php::stock_apply_movement()` owns farm/item locks, available-stock guard, physical quantity update, source-aware ledger insertion, the unit-cost and posted monetary snapshot, and current weighted cost reconciliation. A failed new `USED` after a provisional source reversal must be rolled back **together with** any prior source fact update and reversal, because neither the stock service nor Daily Feed helper independently commits the caller's transaction.
- `lib/stock_service.php::stock_reverse_transaction()` appends a compensating opposite-direction immutable stock movement, marks the original `USED` reversed, and binds both directions with `reversal_of_id`. It invokes `stock_consumption_allocation_persistence_before_source_reversal()` **within the same transaction** to clear any existing linked cost allocation/revision before reversing. Test checks absence of orphan stock/allocation records and original-to-reversal ownership links.
- `lib/stock_costing.php` replays posted receipt/unit/total-cost snapshots to value stock historically; `stock_expected_balance()` sums **all** immutable incoming/outgoing rows so reversal pairs cancel, and `stock_reconciliation()` verifies current physical stock matches the ledger. `stock_consumption_source_resolver.php` is the central source/tenant/cycle owner. These services, not page-local calculations, supply B09 assertions.
- B09 is distinct from B06 full continuity mortality rejection, B08 mortality version replay, B10 role/CSRF boundary, and B11 injected failure *between continuity, feed, mortality and egg allocation writers*. The B09 forced error occurs only after the Feed stock writers to prove a feed-specific atomic caller transaction; it does not assert a B11-wide transaction certification.
